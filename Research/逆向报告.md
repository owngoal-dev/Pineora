# SnowBoard 静态逆向报告（及 ThemeEngine 第一版对照实现）

> 性质说明：本报告是对官方免费版 SnowBoard deb 的**只读静态分析**；`Sources/` 下的 ThemeEngine 代码是按观察到的行为重写的**原创 clean-room 等价实现**，没有复制、反编译转写或逐字节搬运 SnowBoard 的二进制与源码，也不涉及任何付费/授权绕过。
> 全程未安装、未注入、未运行 SnowBoard，未重启 SpringBoard，未操作屏幕。

## 2. 包结构与注入范围

fat 通用二进制的 arm64e 切片偏移曾被误读为截断，改用按切片读取后完整解析。

| 文件 | 作用 | 注入目标（`plists.txt` 证据） |
| --- | --- | --- |
| `Library/MobileSubstrate/DynamicLibraries/Snowboard.dylib` | 入口 tweak | `Bundles: com.apple.UIKit`；`Executables: CarPlay, AppPredictionWidget, Spotlight, ShareUI, WeatherAppTodayWidget, sharingd` |
| `…/AAASnowBoardStub.dylib` | SpringBoard 侧桩 | `Bundles: com.apple.springboard` |
| `usr/lib/SnowBoardBase.dylib` | 主体逻辑（418 个方法） | 被上面两者链接 |
| `Library/PreferenceBundles/SnowboardPrefs.bundle/SnowboardPrefs` | 设置面板（PreferenceLoader） | 设置 App |
| `usr/local/bin/snowboardutil` | 命令行工具 | — |

要点：SnowBoard 的主体逻辑放在一个**共享 dylib**里，由入口 tweak 与 SpringBoard 桩分别加载，所以它天然覆盖 UIKit 层的应用（Spotlight、分享面板、CarPlay 部件等）。导入框架：`@rpath/AAASnowBoardStub.dylib` 等。

## 4. 主题发现与优先级

**设置域（确证）**：`com.spark.snowboardprefs`，文件 `/var/mobile/Library/Preferences/com.spark.snowboardprefs.plist`（`+[SnowBoardPreferencesManager 0x6334]`、`0x6428`，`STRING 0x37dc5`）。`SnowboardPrefs.bundle/Root.plist` 里 `defaults = "com.spark.snowboardprefs"`、`key = Enabled`。

**目录（确证）**：

- `/Library/Themes`（`SnowboardPrefs` 侧 `STRING 0x37b92`；`SnowBoardBase` 侧 `CFSTRING 0x45450`）
- 主题包后缀 `.theme`（`STRING 0x37bd3`）
- 用户自定义图标：`/var/mobile/Media/Snowboard/CustomIcons/`（`CFSTRING 0x46790` 附近，`+[SnowBoardThemeLoader]` 与 `-[SnowBoardFolderViewController]` 都引用）

**与主题选择相关的键（确证存在，语义为推断）**：

| 键 | 引用 | 推断语义 |
| --- | --- | --- |
| `LoadedThemes` | `+[SnowBoardThemeLoader] 0x14f14/0x14f40/0x15800`、`setLoadedThemes:` | 已启用主题路径列表（主题内 `Info.plist` 里也出现同名键） |
| `IconOverrides` | `0x1b050/0x1b164/0x1b7dc`、`addOverride:forBundleIdentifier:`、`getOverrideForBundleIdentifier:` | 单个 bundle id 覆盖到指定主题/文件 |
| `FuzzyBundleIdentifiers` | `0x16638/0x1665c`、`cachedFuzzyBundleIdentifiers`、`NSCache` 类型的 `_cachedFuzzyBundleIdentifiers` | 允许按 bundle id 前缀/模糊匹配（如 `com.apple.mobilesafari` ↔ `com.apple.mobilesafari.something`），带缓存 |
| `ForceLegacyThemes` | `0x17ad4`、`CFSTRING 0x45a30` | 强制按旧版布局解析 |
| `GroupThemes` | `CFSTRING 0x5d100`、`0x10000c9b8` | 主题分组（分组主题共享一套图标） |
| `STLThemeSettings` | 多处 | 单主题内的设置覆盖 |
| `THEME_PACK` / `THEME` / `THEME_INFO` / `THEMES` | `SnowboardPrefs` 侧 `0x37ad6..0x37b80` | 主题打包与主题信息结构键 |

**主题内布局（确证字符串 + 推断的解析顺序）**：

`+[SnowBoardThemeLoader 0x166bc] → "IconBundles"`（`CFSTRING 0x45050`、`STRING 0x37946`）与 `0x16934 → "Bundles"`（`CFSTRING 0x46430`、`STRING 0x38438`）；`0x15a58 → "Info.plist"`。

推断的有效顺序（**未运行验证**）：

1. `Info.plist` 里显式声明的 `Icons`/`IconBundles` 映射
2. `<theme>/IconBundles/<bundleID>@2x.png` 等
3. `<theme>/Bundles/<bundleID>/<name>@2x.png`
4. 旧版布局 `<theme>/<bundleID>/…`（无 `IconBundles`、有 `Bundles` 或旧目录时视为 legacy）

首个命中的主题优先；同层首见优先（`LoadedThemes` 的顺序）。

## 5. 文件名规则（字符串证据）

来自 `SnowBoardIconHolder` 的方法级字符串引用（`stringrefs-by-method.txt`）：

- 倍率后缀 `@`（`0x45cc`、`0x45f4`）、`_alt`（`0x45a4`）、`-large`（`0x4648`）、`_alt.png`（`0x4894`）
- 拼接模板 `%@.png`（`SnowBoardBase` `STRING 0x5e200`）、`%@/%@.png`（`0x5eca0`）、`icon@`（`0x5ea40`）、`appicon`（`0x5ea20`）
- 时钟红点 `ClockIconRedDot`（`0x5e9e0`）

即：`<name>@2x.png`、`<name>@3x.png`、`<name>@2x~ipad.png`、`<name>-large.png`、`<name>_alt.png`，并支持目录 + 文件名两级拼接。

## 6. 图标替换链路

SnowBoard 在 SpringBoard 侧引用到的图标相关符号（`SELREF`）：

```
0x67f90 _setIcon:animated:        0x67fb8 _updateIconImageViewAnimated:
0x688a8 iconImageWithInfo:        0x68930 imageForIcon:
0x693c8 setIcon:                  0x693d0 setIcon:animated:
类名：SBIconView(0x45aad) SBIconImageView(0x46334) SBFolderIconImageView(0x45aec)
      SBLiveIconImageView(0x4577b) SBClockApplicationIconImageView(0x46215)
      SBHClockApplicationIconImageView(0x46235)
```

结合 `SnowBoardIconHolder` 的 `SIHImagePaths`/`SIHAltImagePaths` 关联对象，链路是：**图标视图 → 询问图片 → IconHolder 按主题解析路径 → 解码 UIImage → 交给图标视图**，替换发生在图片层而不是视图层。

### 本机实测（重要修正）

`Research/tools/TEProbe.m` 在独立进程里 `dlopen` 本机 `SpringBoardHome` 做反射（未注入 SpringBoard），iOS 17.3.1 结果：

| 类 | 方法 | 是否存在 |
| --- | --- | --- |
| `SBHIconImageCache` | `-imageForIcon:` | ✅ |
| `SBHIconImageCache` | `-imageForIcon:options:` | ✅（带第二参数，类型未证实） |
| `SBHIconImageCache` | `-cachedImageForIcon:` / `-unmaskedImageForIcon:` / `-realImageForIcon:options:` | ✅ |
| `SBHIconImageCache` | `-purgeAllCachedImages` / `-iconImageDidUpdate:` / `-purgeCachedImagesForIcons:` | ✅ |
| `SBHIconImageCache` | `-iconImageForIcon:` | ❌ 不存在 |
| `SBFolderIconImageCache` | `-gridCellImageForIcon:` / `-iconImageCache` / `-rebuildImagesReferencingIcons:` / `-informObserversOfUpdateForAllFolderIcons` | ✅ |
| `SBFolderIconImageCache` | `-imageForIcon:` / `-purgeAllCachedImages` | ❌ |
| `SBHIconManager` | `-iconImageCache` / `-folderIconImageCache` | ✅（缓存实例来源；该类无 `+sharedInstance`） |

结论：**早期按 `iconImageForIcon:` 写钩子是错的**，已改为 `imageForIcon:` 等；文件夹内的迷你图标同样经 `SBHIconImageCache` 取图，所以不需要单独钩文件夹合成图。

## 7. 刷新链路

- `STRING 0x46c46`（`SnowBoardBase`）：`[SnowBoard Reload] Reloading themes...`
- `-[SnowBoardThemeLoader reloadWithoutExtensions:]`（`METHOD 0x150f4`）、`hasForceRefreshedOnce`、`setLoadedThemesOnlyExistingIcons:`
- `-[SnowBoardExtensionManager notifyExtensionsOfReload]` 与 `CFSTRING 0x5fb80`：`[SnowBoardExtensionManager] Notifying extensions of icon reload...`

推断：重载 = 重扫主题目录 → 清图标图片缓存 → 通知扩展 → 让图标视图重取图。清缓存的实际调用点未在静态证据中定位到（`purgeAllCachedImages` 在设备上存在，但 SnowBoard 用的是哪个选择器未确认）。

## 8. 扩展接口

- 目录 `/Library/SnowBoard/Extensions`（`CFSTRING 0x5fa40`），加载器 `-[SnowBoardExtensionManager loadPath:]`（`METHOD 0x36ba8`）、`loadExtensionsForceAll:`（`0x35a4c`）
- `CFSTRING 0x5fba0`：`[SnowBoardExtensionManager] Creating instance of icon extension: %@`
- 扩展回调：`processIcon:`、`processIcon:skipExtensions:`、`wouldProcessIcon`、`wouldProcessIconWithExtensionIdentifier:`、`extensionsForType:`
- 图标裁切也有扩展旁路：`+[SnowBoardThemeLoader maskedImage:withCrop:skipExtensions:]`（`METHOD 0x197c4`）
- SpringBoard 侧的数据传递：`-[SnowBoardExtensionManager sendToSpringBoard:]`（`0x37cc0`，`sendToSpringBoard:registerForRemote`/`registerForReceive` 成对出现）

这套「图标处理器」接口就是第三方图标扩展（时钟、日历、天气部件等）挂载的地方。

## 9. ThemeEngine 第一版的对应实现

| SnowBoard 行为 | ThemeEngine 实现 | 文件 |
| --- | --- | --- |
| 主题目录扫描 `/Library/Themes/*.theme` | `-themeSearchDirectories`（bootstrap 路径经 `TEBootstrapFilePath`）+ `-reload` | `Sources/TEIconStore.m` |
| `LoadedThemes` / `IconOverrides` / `ForceLegacyThemes` 等键 | 读 `com.spark.snowboardprefs.plist`（兜底 `com.spark.snowboard.plist`），只读不写 | `Sources/TEIconStore.m` |
| 三种布局与 `@2x/@3x`、`-large`、`_alt` 规则 | `TETheme`（主题解析）+ `-iconPathForBundleIdentifier:scale:`（倍率精确命中→回退最大倍率→无后缀文件） | `Sources/TETheme.m`、`Sources/TEIconStore.m` |
| 模糊 bundle id 匹配 | 前缀匹配兜底（`-iconPathForBundleIdentifier:` 内） | 同上 |
| 图标替换点 | 钩 `SBHIconImageCache` 的 `-imageForIcon:`、`-cachedImageForIcon:`、`-unmaskedImageForIcon:`（只带一个参数，签名一致） | `Sources/Tweak.m` |
| 清缓存 + 重绘 | `SBIconController.sharedInstance → iconManager → iconImageCache -purgeAllCachedImages`、`folderIconImageCache -informObserversOfUpdateForAllFolderIcons` | `Sources/Tweak.m` |
| 重载通知 | 监听 `<包 ID>/refresh`、`com.spark.snowboard.refresh`、`…refreshNow`、`…purgeAndUpdateAllIcons` | `Sources/Tweak.m` |

刻意没做的：`-imageForIcon:options:`（第二参数类型未证实，猜错会破坏栈/寄存器约定）、扩展管理器（SnowBoard 的扩展 ABI 未公开）、图标裁切与效果、时钟/日历/部件图标、文件夹合成图。

## 11. iOS 17.3.1 + roothide 的兼容性与局限

1. **路径**：`/Library/Themes` 在 roothide 下属于 bootstrap，进程内必须走 `jbroot()`；`/var/mobile/…` 是真实系统路径，不能加前缀。代码里两处分开处理。
2. **SpringBoard 缓存**：图标图片在多个层次被缓存（`SBHIconImageCache`、图标视图的 layer）。我们直接返回主题图，因此「换主题」即时生效；但「删主题恢复原图」要等重绘，`purgeAllCachedImages` + 文件夹通知是尽力而为。
3. **覆盖范围**：第一版只注入 `com.apple.springboard`。SnowBoard 还注入 `com.apple.UIKit`（含 Spotlight、分享面板、CarPlay 部件等），这些位置的图标本版不会变。
4. **符号风险**：`iconManager`、`purgeAllCachedImages` 等是私有 API，跨 iOS 版本可能改名。代码全部做存在性检查并写日志，装错版本时日志会出现 `TEHooks none` 或 `TEPurge no iconManager`，不会崩。
5. **文件夹图标**：迷你图标由 `SBHIconImageCache` 取图，会跟着变；文件夹整体合成图与网格单元格由 `SBFolderIconImageCache` 合成，本版不接管。
6. **iPad 变体**（`~ipad`）、`_alt`、`-large` 只在解析层支持，未用真实主题验证。
