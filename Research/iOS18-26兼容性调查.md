# iOS 18 / 26 图标取图链兼容性调查

## 证据范围

- 当前设备：iPad8,10，iOS 26.0.1 (23A355)。
- 只读探针：Research/tools/TEIOS26Probe.m。在独立进程加载系统 SpringBoardHome，枚举真实方法编码；arm64e IMP 先去除 PAC 再计算偏移。
- --snapshot 生成仅含当前映像 __TEXT 的分析用 Mach-O，留在忽略的 build/；不加载、不签名、不打包或上传系统代码。用已安装的 Disassembler 插件反汇编，并从实际 selector stubs 解码消息名。
- SDK 对照：注册的 17.4 与按用户要求导入的 18.0。项目仍使用原有 17.4 SDK / CLT 15.3 构建。

## 已证实的变化

18.0 SDK 的 SpringBoardHome 导出里新增：

- SBHIconImageAppearance、SBHLightIconImageAppearance、SBHDarkIconImageAppearance、SBHTintedIconImageAppearance 等类。
- SBHGetApplicationIconImageWithImageAppearance / WithTraitCollection。
- SBHCacheIconImagesForApplicationsWithImageAppearance / WithTraitCollection。

17.4 SDK 不含上述外观类及导出。**这证明外观 API 至少已在 18.0 出现，不证明每个私有 selector 的首次出现版本。** 18.0 SDK 的 SpringBoardHome 没有头文件；未找到 IconRendering.framework，因此不能仅凭 SDK 断言 18 的实现与 26 相同。

26.0.1 运行时签名：

| selector | encoding |
|---|---|
| imageForIcon:imageAppearance:options: | @40@0:8@16@24Q32 |
| cachedImageForIcon:imageAppearance:options: | @40@0:8@16@24Q32 |
| realImageForIcon:imageAppearance:options: | @40@0:8@16@24Q32 |
| imageForIcon:compatibleWithTraitCollection:options: | @40@0:8@16@24Q32 |
| cachedImageForIcon:compatibleWithTraitCollection:options: | @40@0:8@16@24Q32 |
| realImageForIcon:compatibleWithTraitCollection:options: | @40@0:8@16@24Q32 |
| SBIconImageView shouldDisplayImageLayer | B16@0:8 |
| SBIconImageView clearCachedImages | v16@0:8 |
| SBIconImageView updateImageAnimated: | v20@0:8B16 |

反汇编与 selector stub 对照得到：

1. SBIconImageView updateImageAnimated: 根据 shouldDisplayImageLayer 分流到 updateImageSublayerAnimated: 或 updateImageContentsAnimated:。
2. shouldDisplayImageLayer 考虑类的 allowsImageLayer；非方角时可直接选择图层，方角时还查询 effectiveIconImageAppearance.hasGlass。
3. updateImageContentsFromCacheAnimated: 直接调用 imageForIcon:imageAppearance:options:，**不会经过旧的 imageForIcon: / imageForIcon:options: 钩子**。
4. imageCacheRetrievalOptions 的 bit 0 由 showsSquareCorners 取反得出，即蒙版选项。

## 最小兼容策略

- iOS 16/17：保留旧六入口、KVC application 兜底、旧 options 入口始终蒙版的行为；不安装新增外观或图层钩子。
- iOS 18+：只在 selector 存在且完整 ABI 精确匹配时安装六个外观 / trait 入口；不猜测 block 或结构体 ABI。
- iOS 26+：仅当已成功渲染出该图标的主题 UIImage 时，令 shouldDisplayImageLayer 返回 NO，转回系统现有位图分支；非主题图标、停用状态、动态时钟仍走原生结果。
- 无主题图时继续调用各自保存的原 IMP，保留 appearance、trait、options，不全局禁用系统玻璃图标。
- 不改主题解析、偏好存储、角标和时钟实现，不切换编译 SDK，不改变包标识。

## 验证与限制

Research/tools/run-pipeline-tests.sh 是当前 roothide 设备的独立测试入口；它只在自己的进程安装钩子，不注入 SpringBoard、不显示窗口、不写用户偏好。最终运行 37 项检查全部通过，包含旧六入口蒙版及原实现回退语义、新外观 / trait 取图、iPad 尺寸倍率、图层与位图分流、停用恢复和动态时钟旁路。

最终代码的 roothide arm64e 与 rootless arm64/arm64e 调试构建均通过，无构建诊断。roothide 调试包已安装，并在重启 SpringBoard 时通过公开构建标记确认加载；这是注入证据，不是桌面显示效果的证据。

独立进程测试不等于真实桌面测试。iOS 16/17/18 没有本机运行环境，不能宣称这些系统已实机回归；仍需对应系统复测。真实桌面的主题切换、文件夹 / Dock、深浅色 / 透明外观、角标及动态时钟仍须单独核验。
